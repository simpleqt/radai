## 2. 问题诊断：为什么知识库路线解决不了图片一致性

基于当前代码事实（`backend/rag/ingestion/storage/milvus_media_writer.py`、
`backend/rag/retriever_v2/direct_retriever.py:294 retrieve_media`、
`backend/application/tools/providers/multi_kb_images.py`）：

1. 入库时图片与文本分块各自成向量：文本进 `<kb>_chunks`，图片进
   `media_vectors_v2`（以邻近 `chunk_id` 锚定，向量来自 caption/OCR 文本）。
2. 检索时两条链路**独立召回、独立打分**：文本命中不携带其图，图片命中靠
   caption/OCR 与查询的相关性，融合发生在回答前的白名单阶段，不是题干↔受力图
   的结构化绑定。
3. 对基础力学题是致命的：题干常由受力图/结构简图定义，文本分块被召回而图未跟随时，
   模型只能按残缺文本作答；或配上了不相关图片。
4. 且知识库内不存在「一道题」这个可管理实体——无法改难度、标知识点、启停单题；
   题目边界全靠 LLM 抽取纪律（跨页合并、题干完整），无结构保证。
5. 把做题塞进智能体回答里同样不精准：流式生成可能改写题干、漏图、漏选项，
   学生无法逐题作答与判分。**做题必须由 UI 确定性渲染，讲解才交给智能体**（R5）。

结论：题库脱离 RAG 分块建模为结构化业务数据；图片绑定发生在入库解析时；学生经
专门练习模式使用；做题记录成为与提问记录并列的教学分析数据源（R6）；知识库
（multi_kb_search）只做讲解问答的知识支撑。

## 3. 总体架构与数据模型

```text
教师端 /teacher/bank                学生侧边栏「习题练习」 /practice        学生对话(fmca)
  上传docx → 解析 → 确认/标注         做题模式 / 解答模式                  「请讲解 QB-xxx」
       |                                  |                                  |
       v                                  v                                  v
POST /api/v2/teacher/question-bank   GET/POST /api/v2/practice/*      search_question_bank
  (require_teacher)                  (登录学生；题目下发脱敏，          (按 ID 精确取题 →
       |                              服务端判分后返回解析)              讲解；KB 检索仅用于
       |                                  |                              概念/公式支撑)
       |          attempts(做题记录)        |
       +------------------> 教学分析 <------+
       |        question_records(提问,已有) |
       v                                  v
  GET /api/v2/teacher/analytics/*   （提问聚类 × 做题错误 融合报告/大屏，§8）
       |
MySQL question_bank_* 业务表  <——题目图片强绑定——>  MinIO question-bank/ 对象
                                               (稳定 object_name, 签名代理展示)
```

MySQL 四张新表（迁移 `202608170001_add_question_bank_tables`，
SQL `scripts/migrations/add_question_bank_tables.sql`，ORM `backend/db/models/question_bank.py`，
登记进 `backend/db/migrate.py` 的 MIGRATIONS 账本）：

- `question_bank_batches`（上传批次）：id、file_name、file_key（MinIO 原件）、
  status（`parsing`/`parsed`/`confirmed`/`failed`）、parsed_json（解析出的整批题目+
  逐题校验结果，确认前不进题目表）、error、created_by、时间戳。LLM 辅助解析异步时
  复用教师报告的 running 超时回收纪律。
- `question_bank_questions`（题目，一等业务实体）：
  - 内容：question_type（选择/填空/判断/计算/作图/简答）、stem（Text，含选项全文）、
    options_json、answer（Text）、analysis（Text）、score。
  - 标注：difficulty（`easy/medium/hard` 三档，可空=待标注）、chapter、
    knowledge_points_json（字符串数组，取值来自字典表）。
  - 图片：images_json = `[{object_name, caption, seq}]`，**逐题有序强绑定**（§6）。
  - 管理：status（`published`/`disabled`）、source_batch_id、source_name
    （如「2024-2025 期末卷 第 3 题」）、stem_hash（批内查重）、created_by、时间戳。
  - 索引：(status, question_type)、(difficulty)、(chapter)、stem_hash。
  - 标注三重身份：管理维度、学生筛选维度、分析聚合维度——**分析报表的错误率/正确率
    按题目标注的知识点/难度/章节聚合**，标注质量直接决定分析质量，这是「标注」的
    核心价值闭环。
- `question_bank_knowledge_points`（知识点受控字典）：id、name（唯一）、chapter、
  parent_id（可选层级）、sort。种子从教师侧录入；标注只能从字典选择（可申请新增），
  保证检索过滤与**分析聚合的枚举一致性**（自由标签会让报表维度碎片化）。
- `question_bank_attempts`（学生做题记录，兼作分析采集）：id、user_id、question_id、
  answer_json（作答内容）、is_correct（BOOL，可空=主观题待自评）、mode
  （`practice`/`browse`）、created_at；索引 (user_id, created_at)、(question_id)、
  (created_at)。知识点/难度/章节等分析维度**不冗余存储**，聚合时 join questions 表
  （题目编辑罕见，编辑后按最新标注重新聚合即可，无快照一致性问题要付代价）。

属主策略：与教师分析报告（含学生 PII，按属主隔离）不同，题库与练习记录中题库部分是
**课程共享教学资产**——全部 teacher/admin 可管理，操作记审计（`teacher.question_bank.*`）
与 created_by；`attempts` 对学生仅本人可读（与 message_feedback 同款的属主纪律），
对教师提供**聚合视图与错题榜**（个体明细开放度与既有「教师可查看学生对话」一致，
无班级隔离，沿用提问分析的可见性决策）。

## 4. 上传：规范格式与解析流程

### 4.1 Word 模板（v1 唯一格式，随实施提供下载）

每题一个块，固定标记字段，题与题用独立分隔行（`====`）隔开；图片（受力图、结构简图）
直接内嵌在题干标记之后的正文位置：

```text
【题型】计算题
【题干】图示简支梁受均布载荷……（此处粘贴受力图图片；公式用 LaTeX 文本或图片）
【选项】A. …  B. …            （仅选择题）
【答案】…
【解析】…
【难度】中等                    （简单/中等/较难，可留空后补标注）
【知识点】平面力系的平衡；受力图   （分号分隔，多个）
【章节】第 3 章 平面力系
【来源】2024-2025 期末卷 第 3 题
====
```

### 4.2 解析管道（确定性优先，LLM 只做受门控的辅助）

1. 主路径：pypandoc（已是 `export_document` 依赖）docx→Markdown——OMML 公式自动转
   LaTeX、图片按文档顺序导出；随后按标记切分题目块、逐字段解析，图片按出现位置
   锚定到所属题目的题干。python-docx（已有依赖）做标题/表格兜底。
2. 图片落 MinIO：`question-bank/{batch_id}/{question_uuid}/{seq}.{ext}`（稳定
   object_name 即持久身份，绝不存带 exp/sig 的 URL）。单张 ≤10MB、每题 ≤6 张、
   docx ≤20MB、单批 ≤500 题（与既有 uploads 限制同风格，可调）。
3. 逐题校验报告：缺题干/答案、题型未知、知识点不在字典、图片缺失、批内重复
   （stem 规范化哈希）分级为 error/warning；error 题不入库，warning 可由教师在预览
   界面修正后放行。
4. 教师确认门：解析结果暂存 `batches.parsed_json`，教师在预览页逐题核对/补标注后
   `POST /batches/{id}/confirm` 才写入 questions 表（默认 `published`）。**未确认批次
   不污染题库**。
5. LLM 辅助解析（可选开关，v1 仅对「未按模板的半结构化 Word」）：经 ingestion scope
   模型把文档结构化为同一题目 JSON，再走同一个教师确认门；异步任务 + 轮询，对齐教师
   分析报告的 running/超时回收模式。扫描件 PDF（MinerU OCR 后再 LLM 解析）为阶段 2。

### 4.3 明确的格式纪律（写入模板说明）

- 答案/解析须教师自填，系统不生成、不推断（沿用旧 schema 的宁缺毋滥纪律，但由
  「教师确认门」结构化保证，不再依赖模型自觉）；
- 公式建议 LaTeX 文本或图片；Word 公式编辑器内容经 pandoc 转 LaTeX，转换失败降级为
  警告。

## 6. 学生练习模式：侧边栏专门入口（题库主入口，R5）

### 6.1 为什么是专门模式而不是智能体回答

- **确定性**：题干/选项/图片由前端按 `images_json` 原样渲染，图必随题、无改写无遗漏；
  流式回答做不到这个保证。
- **可作答可判分**：逐题提交、服务端判分、做题后解锁解析；对话无法承载作答交互。
- **精准使用**：侧边栏直达，按知识点/难度/题型筛选，学生不需要会「提问技巧」。
- **职责分离**：智能体回答退回「讲解」本职，知识库只做讲解问答的知识支撑，
  题目与知识库检索解耦——不一致问题从链路上消失。
- **分析闭环**：每次作答自动落 `attempts`，为教学分析提供结构化做题数据（R6），
  无需旁路采集。

### 6.2 前端（`frontend_fmca`）

- 侧边栏 `AppSidebar.vue` 新增「习题练习」入口：登录用户可见（student/user 与
  teacher/admin），游客端（`guest/` 轻量应用）v1 不加，引导登录。
- 路由 `/practice/*`（列表/做题/解析），视图 `frontend_fmca/src/views/practice/`，
  API 客户端 `frontend_fmca/src/api/practice.ts`。页面形态对齐 custom-learning 的
  独立学习页（非 ne-full 内嵌）。
- 列表页：章节/知识点/难度/题型/关键词筛选（消费教师标注），显示来源与题图缩略。
- **做题模式**：逐题作答——选择/判断点选即判；填空提交判；计算/作图/简答提交后
  对照参考答案与解析**自评**（「会了/没掌握」按钮，v1 不做 LLM 判分）。提交后本题
  解析解锁，错题进「错题本」（按 attempts 过滤 is_correct=false，支持重练）。
- **解答模式**（浏览态）：直接展示题干+图片+答案+解析，供复习；与做题模式共用
  题目渲染组件，差别仅是解析是否立即可见。
- 题干含 LaTeX（pandoc 已转为 LaTeX 文本），复用 `MarkdownRenderer` 渲染；题图经
  签名代理 URL 直接 `<img>` 渲染（不需要聊天链路的 `[IMAGE:nnn]` 令牌）。
- 每题「问智能体」按钮：跳转 fmca 会话页并预置提问「请讲解试题 QB-{id}」
  （见 §7）。

### 6.3 后端（`backend/api/routers/practice.py`，`prefix=/api/v2/practice`，agent 角色挂载）

- `GET /questions`：仅 `published`；**下发脱敏**——不含 answer/analysis（对齐
  custom_learning `_QUIZ_PRIVATE_FIELDS` 的教训：答案绝不经列表/详情接口下发，
  否则 F12 即抄答案）。筛选参数同列表页。
- `POST /questions/{id}/check`：提交作答 → 服务端判分（选择/判断精确匹配；填空
  规则归一化判分，对齐 `_grade_quiz` 纯规则风格）→ 写 `question_bank_attempts` →
  返回判定 + **此时才返回**答案/解析（主观题返回参考答案与解析供自评）。
- `GET /questions/{id}?with_solution=1`：解答模式浏览态的显式解析通道（同一脱敏
  收敛点，模式参数服务端校验）。
- `GET /attempts`、`GET /attempts/wrong`：本人做题记录与错题列表（属主隔离，
  他人 404/403）。
- 图片签名代理 `/api/v2/files/qb-image`：HMAC 方案与 kb-image 同源，密钥为空
  fail-closed；只按稳定 object_name 校验，不暴露 MinIO 凭据/裸对象路径。

## 7. 会话内讲解：题目按 ID 精确取回，知识库只做支撑

新工具 `search_question_bank`（`backend/application/tools/providers/question_bank_tool.py`，
registry.yaml 登记 `domains: [fundamental-mechanics-course]`、只读、并行安全，
加入 `fmca_default` policy 的 include；fmca.yaml 无需改动）：

1. 参数：`question_id`（精确取题，讲解主路径）与可选 `keywords/knowledge_point/
   question_type/difficulty/limit`（学生说「再来几道类似的题」时列举并引导去练习模式）。
2. `question_id` 命中即整题返回：题干、选项、答案、解析、图片——作为**服务端确定性
   上下文**，不经任何向量/关键词检索；工具 instructions 明确「讲解试题优先按
   QB- 编号取题；严禁从知识库检索题目本体」。
3. 图片沿用聊天令牌机制：`ImageURLRegistry.register(url, caption)` 逐张注册，输出以
   `![题图n]([IMAGE:nnn])` 引用，答案管线 `resolve_all` 换签名代理 URL，会话目录以
   稳定 object_name 持久化 `registered_images`（签名只是展示态，不是身份）。
4. 概念/公式/推导讲解照旧走 `multi_kb_search`（知识库职责不变）；fmca prompt profile
   增补一条分工说明：题目来自题库工具，知识来自知识库检索。
5. 相似题向量检索（阶段 2）：题干侧索引专用 Milvus collection（模式对齐 synth_query
   side index：published 才写、停用/删除即删行）。

## 8. 教学分析融合：提问 × 做题（R6，扩展已上线的 question_analytics）

既有教师分析只看「学生问了什么」（`course_question_records` → 聚类报告）。本方案把
「做错了什么」（`question_bank_attempts` join 题目标注）并入同一分析域，让两类信号
互相印证——学生**问的**未必是不会的（可能只是查公式），**错的**才是掌握度证据；
两者交叉的才是真薄弱点。

### 8.1 数据与服务（`backend/application/question_analytics/` 扩展，无新表）

- 统计层（`collector.py` 风格的确定性聚合，先于任何 LLM）：
  - 练习总量/活跃做题人数/总体正确率及趋势（按日）。
  - 按知识点聚合：错误率 TOP、做题量 TOP、正确率排行（一并提供样本量，防小样本误读）。
  - 按难度/章节/题型聚合：如「中等题正确率骤降」定位难度断层。
  - 高频错题榜：错误次数 TOP 题目（题干摘要+知识点+错误率+题图）。
- 聚类层（`clustering.py`）：LLM 语义聚类的输入从纯提问文本扩展为「提问文本 +
  该时间窗错题知识点摘要」，让聚类主题与练习错误对齐；LLM 失败仍降级纯统计
  （`llm_status=degraded` 纪律不变）。
- 报告层（`service.py`）：`result_json` 在既有提问章节外新增
  - `practice_summary`：上述确定性统计；
  - `cross_insights`：提问聚类簇 ↔ 错题知识点的对照矩阵——「问得多且错得多」= 共性
    薄弱点（建议优先讲解）；「问得多但正确率高」= 概念澄清型提问（讲概念即可）；
    「错得多但没人问」= 沉默的薄弱点（建议课堂主动覆盖，最易被提问分析漏掉）；
  - `recommended_exercises`：按薄弱知识点从题库抽题（published、按难度递进取
    3-5 题/知识点），给题号与摘要，教师在管理页一键定位。
- 时间窗/抽样/冷却/单飞/stale 回收等既有报告生命周期机制全部复用，不新增状态语义。

### 8.2 API（`backend/api/routers/teacher_analytics.py` 扩展，不新建路由域）

- `GET /insights`（预制大屏，确定性统计无 LLM）：新增练习维度卡片与图表——做题量
  与正确率趋势、错题知识点 TOP10、高频错题 TOP10、难度正确率分布；提问维度保持不变。
- `POST /reports`：请求体不变（时间窗），生成时自动并入练习数据；题库为空时练习
  章节返回 `empty` 占位（提问分析独立可用，不因题库未导入而失败）。
- `GET /reports/{id}`：返回融合报告；`report-detail.vue` 渲染新章节（错题榜带题图、
  交叉洞察表、推荐题目列表）。
- `GET /practice/overview`：班级练习总览（教师视角的聚合明细，含高频错题翻页）。

### 8.3 前端（`frontend_fmca/src/views/teacher/`）

## 11. 明确不做

- 不恢复旧路线：不再为习题建专用知识库/抽取 schema（9cea07e 已废弃删除）；
  教材讲解库不动，知识库定位收敛为「问答知识支撑」（R5）。
- 做题不进智能体回答流：题目作答/判分/解析展示由练习模式承载；对话只做讲解。
  `fmca.yaml` 现有绑定不动（其 default_kb_ids 失效问题是独立运维事项，不与本方案
  捆绑）。
- 题库不做按教师属主隔离（共享教学资产，审计+created_by 追溯）；练习记录学生侧
  仅本人可读，教师侧只提供聚合视图与错题榜（个体明细阶段 2 另行评审）。
- 分析不引入新的报告状态机：复用既有报告生命周期的全部护栏（单飞/冷却/stale 回收/
  抽样上限），只扩数据源与报告结构。
- 游客端（`guest/`）v1 不提供练习模式。
- 不做题目自动批改升级与组卷判分（属 custom_learning 既有域，阶段 2 评估复用）。

## 附录：实施与设计的差异（2026-08-17 v1 落地记录）

1. **解析器主路径**：实现为 python-docx 确定性提取为主（`a:blip` 图片按文档顺序
   锚定），pandoc（docx→markdown，OMML 公式→LaTeX）为可选增强路径，失败自动回退；
   单测固定走 python-docx（`QUESTION_BANK_DISABLE_PANDOC=1`）。设计稿的「pandoc 主
   路径」顺序对调——任何环境可用的兜底成为默认，行为更可预测。
2. **题干与选项分离**：设计稿注释「stem 含选项全文」沿袭旧抽取路线；实现为
   `stem` 纯题干 + `options_json` 结构化选项（练习页按选项渲染单选），模板仍要求
   选项写在【选项】标记下。
3. **主观题自评**：`check` 接口增加 `self_review` 参数——服务端客观判分优先，
   主观题按学生「已掌握/仍不会」自评落 `is_correct`（设计稿 v1 未定义该通道）。
4. **「问智能体」跳转**：实现为 `/app?q=请讲解试题 QB-{id}` 预填 composer
   （仅 frontend_fmca 的 ne-full index.vue 支持该 query，未动四端共享契约文件）。
5. **已知限制**：批次废弃后的孤儿图片对象暂无自动清理任务；分值字段模板未设独立
   标记（可在编辑页补）；阶段 2 项（向量相似题/Excel/扫描件/LLM 判分/个体明细）未动。
