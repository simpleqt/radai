## 二、沙箱架构：核心问题澄清

### 问题：切换到 AIO Sandbox 后需要每用户一个容器吗？

**答案：不需要。** 这是理解整个方案的关键。

#### AIO Sandbox 的定向解析

```
AioSandboxProvider 关键参数：
  replicas: 最大并发沙箱容器数（默认 3），超出时驱逐 LRU 容器
  idle_timeout: 空闲超时自动释放（默认 600 秒）
```

AIO Sandbox 设计的是**固定容量的容器池**，不是每用户/每线程创建一个新容器。

#### 为什么不需要每用户一个容器

当前架构用**文件系统路径**而不是**容器边界**实现用户隔离：

1. `ThreadDataMiddleware.before_agent()` 根据内部键 `u_{uid}__t_{tid}` 生成目录路径，写入 state 的 `thread_data`
2. `sandbox/tools.py` 中所有文件工具（`read_file`、`write_file`、`bash`、`ls`）都从 `runtime.state["thread_data"]` 取路径，**不接受任意路径输入**
3. `validate_local_tool_path()` 验证只允许 `/mnt/user-data/...` 前缀，`_validate_resolved_user_data_path()` 再次验证解析后路径必须在 `workspace_path`/`uploads_path`/`outputs_path` 三个目录之内
4. 沙箱容器内看到的是 `/mnt/user-data/`，host 侧实际挂载的是该线程的用户目录

**结论：隔离由路径层保证，沙箱容器可以多线程共用（通过 acquire/release + LRU 池复用）。**

#### Local vs AIO Sandbox 对比

| 维度 | Local（当前） | AIO Sandbox |
|---|---|---|
| 隔离机制 | 路径隔离 + 进程共享 | 路径隔离 + 容器（更强边界） |
| 用户间文件可见吗 | 通过路径规则防止，但进程共享 | 容器内只挂载当前线程目录 |
| 沙箱数量 | 1 个全局单例 | `replicas` 个容器池 |
| 是否每用户一个 | 否 | 否（池化复用） |
| 生产推荐 | 仅限可信内部环境 | ✅ 推荐 |

## 三、AIO 模式：容器化隔离与资源管理

### 1. 核心参数解析

`sandbox` 配置示例：
```yaml
sandbox:
  use: <aio-sandbox-provider-class>
  image: enterprise-public-cn-beijing.cr.volces.com/vefaas-public/all-in-one-sandbox:latest
  replicas: 3
```

- **`replicas: 3`**：宿主机上允许同时运行的"活跃 + 待命"容器的最大数量（软限）
- **非静态占用**：系统启动时不会预先创建 3 个容器，而是根据用户的工具调用请求**按需创建**
- **LRU 淘汰机制**：当并发活跃线程达到 3 个，且有第 4 个新线程需要沙箱时，系统会自动销毁最久未使用的容器以释放名额

### 2. 隔离逻辑：动态挂载 (Dynamic Mounting)

虽然容器是复用的，但**数据是完全隔离的**：
- 容器启动或分配给具体线程时，会动态将其对应的 host 目录（`users/{uid}/threads/{tid}/`）挂载到容器内的 `/mnt/user-data/`
- 容器进程只能看到当前线程的数据，无法嗅探其他线程或宿主机的敏感文件

### 缺口 2：对话删除导致的数据残留 ⭐高优先级

**问题描述**：
1. `delete_conversation()` 仅做软删除（`is_deleted = True`），`base_dir/users/{uid}/...` 目录未清理，可能导致后续重建同名会话时历史数据串连泄露
2. 当前使用的 `AsyncSqliteSaver`（来自 `langgraph.checkpoint.sqlite.aio`）**没有 `adelete()` 方法**，无法通过 API 删除 checkpoint
3. 软删除记录 + `UniqueConstraint("user_id", "thread_id")` 导致重建同名会话时旧记录仍存在但 `is_deleted=True`，会话在列表中不可见

**位置**：`backend/api/routers/conversations.py:delete_conversation()`

**修复计划**：

```python
from backend.core.config import get_paths, build_internal_thread_key

async def delete_conversation(
    thread_id: str,
    request: Request,
    user: User = Depends(get_current_user),
    session: AsyncSession = Depends(get_async_session),
):
    result = await session.execute(
        select(Conversation).where(
            Conversation.thread_id == thread_id,
            Conversation.user_id == user.user_id
        )
    )
    conv = result.scalar_one_or_none()
    if not conv:
        return {"success": True}

    conv.is_deleted = True
    await session.commit()

    # ===== 新增代码 =====

    internal_thread_id = build_internal_thread_key(user.user_id, thread_id)

    # 清理 Checkpointer 记忆切片
    # 注意：AsyncSqliteSaver 没有 adelete() 方法，需要直接操作数据库
    try:
        checkpointer = get_checkpointer_from_request(request)
        if hasattr(checkpointer, "conn"):
            import aiosqlite
            await checkpointer.conn.execute(
                "DELETE FROM checkpoints WHERE thread_id = ?",
                (internal_thread_id,),
            )
            await checkpointer.conn.execute(
                "DELETE FROM checkpoint_blobs WHERE thread_id = ?",
                (internal_thread_id,),
            )
            await checkpointer.conn.execute(
                "DELETE FROM checkpoint_writes WHERE thread_id = ?",
                (internal_thread_id,),
            )
            await checkpointer.conn.commit()
    except Exception as e:
        logger.warning(f"清理 checkpointer 失败: {e}")

    # 删除沙箱线程宿主目录（复用 Paths.delete_thread_dir）
    try:
        get_paths().delete_thread_dir(internal_thread_id)
    except Exception as e:
        logger.warning(f"清理沙箱线程目录失败: {e}")

    return {"success": True}
```

> **重要说明**：
> - `AsyncSqliteSaver` 没有 `adelete()` 方法，必须直接操作底层 SQLite 连接删除 checkpoint 记录
> - 目录清理应复用 `Paths.delete_thread_dir()` 而非手写 `shutil.rmtree`
> - Checkpointer 表名（`checkpoints`、`checkpoint_blobs`、`checkpoint_writes`）取决于 LangGraph 版本，实施时需确认

### 缺口 2b：删除后重建同名会话不可见 ⭐高优先级

**问题描述**：
`Conversation` 表有 `UniqueConstraint("user_id", "thread_id")`，软删除后旧记录仍存在。当 `agent.py` 尝试为同名 thread_id 创建新会话时，`scalar_one_or_none()` 返回旧记录（`is_deleted=True`），导致跳过创建，新会话在列表中不可见。

**位置**：`backend/api/routers/agent_runtime.py`（会话创建逻辑）

**修复计划**：

在 `agent.py` 的会话创建逻辑中，检查到已存在但已删除的记录时，恢复其可见性：

```python
result = await session.execute(
    select(Conversation).where(
        Conversation.thread_id == request_thread_id,
        Conversation.user_id == user.user_id
    )
)
existing_conv = result.scalar_one_or_none()
if not existing_conv:
    new_conv = Conversation(
        user_id=user.user_id,
        thread_id=request_thread_id,
        title=payload.question[:30] + ("..." if len(payload.question) > 30 else "")
    )
    session.add(new_conv)
elif existing_conv.is_deleted:
    existing_conv.is_deleted = False
    existing_conv.title = payload.question[:30] + ("..." if len(payload.question) > 30 else "")
await session.commit()
```

**验收标准**：
1. 用户删除会话后重建同名会话，LangGraph 不返回旧历史（checkpointer 已清理）
2. 重建的同名会话在列表中正常可见

### 缺口 3：Local Sandbox 配置存在安全风险 ⭐安全卡点

**问题描述**：
`backend/config.yaml` 使用 `LocalSandboxProvider + allow_host_bash: true`，本地开发模式存在进程级变量窃取风险。恶意脚本可能通过 `os.environ` 获取敏感信息。

**修复计划**：

生产部署时切换到 `AioSandboxProvider`：

```yaml
# backend/config.yaml
sandbox:
  use: <aio-sandbox-provider-class>
  image: enterprise-public-cn-beijing.cr.volces.com/vefaas-public/all-in-one-sandbox:latest
  replicas: 5
  idle_timeout: 600
  allow_host_bash: false  # 关闭宿主机直通越界模式
```

> **注意**：此修改为运维配置变更，需配合容器镜像构建。

## 六、Skills 机制：与沙箱的关系

Skills 通过 `/mnt/skills` 只读挂载进容器，本质是**工具包装层**，不影响用户隔离：

```
/mnt/skills/public/xxx/SKILL.md  ← 只读，所有用户共享
/mnt/user-data/workspace/        ← 读写，按 thread_id 隔离
/mnt/user-data/uploads/          ← 读写，按 thread_id 隔离
/mnt/user-data/outputs/          ← 读写，按 thread_id 隔离
```

**结论**：Skills 层无需改动。

| 场景 | 预期行为 |

## 八、不需要做的事

- **不需要每个用户一个 AIO 容器**：沙箱是工具执行环境，数据隔离由路径层保证
- **不需要改 Skills 系统**：Skills 是只读工具包装，与用户数据无关
- **不需要改知识库上传链路**（`/api/uploads` → MinIO）：那是另一套体系
- **不需要改前端**：外部 `thread_id` 不变，用户感知不到内部键
- **不需要创建 `ScopedStorage` 类用于沙箱**：沙箱内文件操作不涉及 MinIO，走 `sandbox/tools.py` 即可。但非沙箱（原生）环境的 MinIO 工具需要 `ScopedStorage`，见 [原生环境方案](./原生环境_非沙箱_用户隔离实施方案.md)
