## 1. 总体实现进度概览

| 阶段 | 方案目标 | 实现状态 | 说明 |
|------|----------|----------|------|
| Phase-1 | 文本 chunk 入库 + Path-B/C 召回 + 软删除 | ✅ 已完成 | TXT/MD/PDF/DOCX 均可入库；Milvus chunk、Redis BM25、MySQL job/chunk/block 元数据闭环 |
| Phase-2 | 实体关系、Schema、质量门控、Path-A/D | ✅ 主体已完成 | LLM/VLM 抽取、YAML Schema、quality_gate、Milvus entities_v2、Nebula Path-D 均已接入 |
| Phase-3 | 多模态 Block、Staging、CommitWriter 状态机 | ✅ 骨架已完成 | ParserRouter/BlockBuilder/VLM 图片描述、MinIO staging、七阶段提交均已落地 |
| Phase-4 | 修复 Worker、指标、版本切换 | ⚠️ 部分完成 | repair_worker、Prometheus metrics、健康检查已有；embedding retry worker 等待补 |
| Phase-5 | 生产加固、迁移工具、A/B 评测 | ⚠️ 初期 | shadow_rebuild、eval 脚本已有；全量压测与可选迁移工具待运营验证 |

**已打通链路**：`SELF_INGESTION` 开启后，`PendingIngestProcessor` / `StartupTaskProcessor` 将 `ingestion_backend=self_ingestion` 的任务路由至 `SelfIngestionPipeline`，经 ParserRouter → BlockBuilder → LLM/VLM 抽取 → Embedding → Staging → CommitWriter 写入 MySQL 元数据 / Milvus 向量 / Redis BM25 / NebulaGraph 图谱，最终由 `SelfDirectRetrieverV2` 四路融合召回。

**与方案的主要差异**：

1. 表格 `table_summary`、公式 `variable_explanation` 已补独立 LLM 摘要增强管线，在 BlockBuilder 构造 chunk 前写入 block metadata；真实业务文档效果仍需 E2E 验证。
2. 实体规范化仅为「同类型 + canonical_name 合并」，**未实现同义词字典、向量 Top-K 聚合、LLM 语义裁决**。
3. `Source Registrar` 未独立成模块，逻辑内嵌于 `pipeline._register_doc`。
4. 当前 Schema 校验脚本要求 `kb_self_ingest_jobs` / `kb_self_chunks` 存在，`kb_self_blocks` 与旧 MySQL 图谱/质量表不存在；生产/预发库仍需确认迁移已执行。
5. `HybridRetriever` 与 retrieval pipeline 的 hybrid 直连合并均已实现，但公开 KB 创建/切换 API 目前主要暴露 legacy/self，hybrid 仍属灰度/配置能力。
