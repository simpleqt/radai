# 原生环境（非沙箱）用户隔离与存储工具实施方案

> **文档状态**：✅ 已落地，2026-07-09 按当前代码校正。
> **适用范围**：非沙箱/原生工具访问 MinIO、用户文件、对话附件和运行时工件时的用户隔离。
> **不适用范围**：知识库上传 `/api/v1/uploads/*` 走 KB 权限体系和公共 KB bucket，是设计例外。

---

## 一、目标与背景

原生环境没有容器级文件系统边界，因此必须在代码层强制保证：

- 模型和工具不能伪造 `user_id` 或任意 MinIO 前缀。
- 用户文件对象必须落在 `users/{user_id}/...` 下。
- 本地生成文件只能来自当前用户运行时目录。
- 历史无用户前缀路径不能作为自动 fallback 被读取。

## 二、身份解析

模块：`backend/core/auth/identity.py`

当前已实现：

```python
def get_current_identity(config: RunnableConfig) -> tuple[str | None, str]:
    thread_id = config.get("configurable", {}).get("thread_id", "")
    return parse_internal_thread_key(thread_id)

def require_user_id(config: RunnableConfig) -> str:
    user_id, thread_id = get_current_identity(config)
    if user_id is None:
        raise PermissionError(...)
    return user_id
```

解析逻辑复用 `backend/core/thread_key.py`。登录用户内部 key 为 `u_{uid}__t_{tid}`；guest 设备态 key 为 `g_{device}__t_{tid}`，不解析为普通用户文件 owner。

## 三、ScopedStorage 当前实现

模块：`backend/core/storage/scoped_storage.py`

```python
class ScopedStorage:
    def __init__(self, user_id: str, thread_id: str):
        self.prefix = f"users/{user_id}/threads/{thread_id}/artifacts/"
        self.bucket = get_user_minio_bucket_name()
```

### 3.1 API 与安全语义

| 方法 | 当前语义 |
| :--- | :--- |
| `read_file(filename)` | 只读取 `users/{uid}/threads/{tid}/artifacts/{filename}`；不回退 `artifacts/{thread_id}/...` |
| `save_file(filename, content, content_type)` | 写入当前 thread artifact 前缀 |
| `save_local_file(object_name, local_file_path)` | 要求 `object_name.startswith("users/{uid}/")`，否则 `PermissionError` |
| `list_objects(prefix, recursive)` | 只列当前 `self.prefix` 下对象 |
| `delete_all_files()` | 只删除当前 `self.prefix` 下对象；MinIO 删除失败会抛异常 |

### 3.2 与历史设计的差异

历史方案曾提出 `read_file()` 双读：

```text
users/{uid}/threads/{tid}/artifacts/{filename}
artifacts/{thread_id}/{filename}
```

当前实现已移除第二条 fallback。原因是 `artifacts/{thread_id}/...` 没有 `user_id` 组成，不能可靠授权，继续自动读取会扩大横向越权面。

## 四、用户文件服务

模块：`backend/services/user_file_service.py`

### 4.1 统一上传登记

`prepare_uploaded_user_file()` 是个人文件和对话附件的共同入口：

- 校验 `storage_scope in {"personal", "chat"}`。
- `storage_scope="chat"` 时必须传 `thread_id`。
- 使用 `ChatFileParser` 解析文件。
- 上传原始文件、提取图片到用户 MinIO bucket。
- 写 `UserFile` 行，`owner_user_id=user_id`，`status="active"`。

对象路径：

```text
personal:
  users/{owner_user_id}/personal-files/{file_id}/{filename}
  users/{owner_user_id}/personal-files/{file_id}/images/{image_name}

chat:
  users/{owner_user_id}/threads/{thread_id}/chat-files/{file_id}/{filename}
  users/{owner_user_id}/threads/{thread_id}/chat-files/{file_id}/images/{image_name}
```

### 4.2 生成工件登记

`register_local_artifact_for_thread()` / sync 版本：

- 从 `internal_thread_id` 解析 `user_id` 和外部 `thread_id`。
- 只允许登记 `get_paths().thread_artifacts_dir(internal_thread_id)` 下的文件。
- 使用 `resolve()` + `relative_to()` 防路径穿越。
- 写入 `UserFile(source_type="local")`。

`register_minio_artifact_for_thread()` / sync 版本：

- 从内部 key 解析用户。
- 写入 `UserFile(source_type="minio")`。
- 由下载路由再次校验对象必须位于用户授权范围。

### 4.3 下载权限

`resolve_user_file_for_download()` 当前规则：

1. 文件不存在 → `not_found`
2. `status != active` → `inactive`
3. `owner_user_id == current_user_id` → allow
4. `user_file_permissions` 存在未过期 `read` 或 `download` 授权 → allow
5. 否则 deny

`write_download_audit()` 会记录 allow/deny、reason、IP、User-Agent。

## 五、路由侧强校验

### 5.1 `/api/v2/files/*`

模块：`backend/api/routers/files.py`

- MinIO artifact 下载只允许 `users/{current_user_id}/threads/...`。
- 用户文件下载要求 bucket 为 `get_user_minio_bucket_name()`，对象名以 `users/{owner_user_id}/` 开头。
- 本地文件下载只允许：

```text
base_dir/users/{owner_user_id}/threads/.../files/artifacts/...
```

并拒绝 `/etc`、`/proc`、`/sys`、`/dev`、`/boot`、`/root`、`/var`、`/tmp`、`/usr`，以及符号链接。

### 5.2 `/api/v1/generated-files/save`

模块：`backend/api/routers/my_files.py`

保存生成文件到个人文件夹时必须且只能提供一种来源：

- `local_abs_path`：必须在当前用户 `base_dir/users/{uid}/threads/.../files/artifacts/...` 内。
- `storage_object`：bucket 必须是用户桶，object 必须以 `users/{uid}/` 开头，且路径段不能含 `.`、`..` 或空段。

## 六、对话附件解析与检索

对话附件上传走 `/api/v2/chat-files/upload`：

1. `read_upload_with_limit()` 限制单文件 50MB、单次最多 10 个文件。
2. `prepare_uploaded_user_file(storage_scope="chat")` 解析并上传。
3. 写 `SessionFile(session_id=thread_id, user_id=user.user_id, file_id=...)`。
4. 长文档写入 `ChatFileIndexManager`，索引 key 为 `(user_id, thread_id)`。
5. 检索工具 `chat_file_search` 由 `create_scoped_chat_file_search_tool(thread_id, user_id=...)` 创建，只读取当前用户当前会话索引。
6. 索引 miss 时可从 `UserFile + SessionFile` 重建当前用户当前会话的 long_doc 索引。

## 七、知识库上传例外

模块：`backend/api/routers/uploads.py`

KB 上传链路写公共 KB bucket：

```text
pending/{kb_id}/{file_id}/{filename}
```

隔离不依赖 `ScopedStorage`，而依赖：

- `verify_api_key()`
- `require_kb_access(session, kb_id, auth, access="write")`
- `PendingFile.created_by == auth.user_id`
- KB owner/admin 体系

因此 `uploads.py` 使用 `settings.minio_bucket_name` 是当前设计，不应按用户文件桶修正。

## 九、验收标准

| 场景 | 预期 |
|---|---|
| 原生工具读取 `artifacts/{thread_id}/x` | 拒绝或 FileNotFound，不做 legacy fallback |
| 工具保存 MinIO 对象到 `users/other/...` | `PermissionError` |
| 用户 B 下载用户 A 的 `file_id` | 403，并写 deny 审计 |
| 用户保存生成文件传入 `/tmp/x` | 403 |
| 对话附件长文档检索 | 只命中 `(user_id, thread_id)` 对应索引 |
| KB 上传 | 非 KB owner/admin 无法写入目标 KB |
