# 原生环境（非沙箱）用户隔离与存储工具实施方案

> **文档状态**：✅ 已完成 (COMPLETED)
>
> **关联说明**：
> - 本方案聚焦 **MinIO 存储层**的用户隔离（非沙箱/原生工具）
> - [用户级隔离实施方案](./用户级隔离实施方案.md)：沙箱文件系统隔离
> - Skill 动态加载机制见 [skill_dynamic_tool_loading_plan.md](./skill_dynamic_tool_loading_plan.md)
>
> 沙箱模式不需要 `ScopedStorage`，因为文件操作走 `sandbox/tools.py` 的路径校验。

## 一、目标与背景

本方案旨在解决智能体在"原生环境（Native/Non-Sandbox）"中执行时，由于缺乏容器级隔离而产生的安全风险。通过**代码层面的封装**和**身份上下文的强制注入**，确保用户只能访问属于自己的数据。

**核心目标：**
- **不可伪造性**：模型无法通过参数篡改访问路径。
- **透明隔离**：开发者调用工具时，隔离逻辑自动生效。
- **架构统一**：Native 与 Sandbox 隔离策略在逻辑层保持对等。

## 二、架构设计与封装接口

### 1. 身份提供者 (Identity Provider)
**模块**：`backend/core/auth/identity.py` ✅ 已实现

统一从任务上下文（`RunnableConfig`）中解析身份。所有 Native 工具不再从入参接收 `user_id`。

```python
def get_current_identity(config: RunnableConfig) -> tuple[str | None, str]:
    """从 config['configurable']['thread_id'] 解析出 (user_id, external_thread_id)
    
    注意：parse_internal_thread_key() 返回 tuple[str | None, str]，
    user_id 可能为 None（当 thread_id 不符合 u_{uid}__t_{tid} 格式时）。
    调用方必须使用 require_user_id() 校验。
    """
    thread_id = config.get("configurable", {}).get("thread_id", "")
    return parse_internal_thread_key(thread_id)

def require_user_id(config: RunnableConfig) -> str:
    """从 config 中解析 user_id，若为 None 则抛出 PermissionError"""
    user_id, thread_id = get_current_identity(config)
    if user_id is None:
        raise PermissionError(
            f"无法从 thread_id 解析出 user_id，拒绝操作: {thread_id}"
        )
    return user_id
```

**当前状态**：解析逻辑已存在于 `backend/core/thread_key.py` 的 `parse_internal_thread_key()`，可直接复用。

### 2. 作用域存储接口 (Scoped Storage Interface)
**模块**：`backend/core/storage/scoped_storage.py` ✅ 已实现

工具不再直接操作 MinIO Client，而是通过一个具备作用域的对象进行交互。

```python
class ScopedStorage:
    """MinIO 存储的作用域封装，确保用户只能访问自己的数据"""

    def __init__(self, user_id: str, thread_id: str):
        self.user_id = user_id
        self.thread_id = thread_id
        self.prefix = f"users/{user_id}/threads/{thread_id}/artifacts/"

    async def read_file(self, filename: str) -> bytes:
        """读取用户目录下的文件"""
        object_name = f"{self.prefix}{filename}"
        # ... 调用 MinIO client

    async def save_file(self, filename: str, content: bytes, content_type: str = "application/octet-stream") -> str:
        """保存文件到用户目录，返回下载 URL"""
        object_name = f"{self.prefix}{filename}"
        # ... 调用 MinIO client，返回 presigned URL
```

**当前状态**：`ScopedStorage` 已封装 MinIO 的作用域读写、上传、列举与清理能力，`backend/core/tools/minio_tools.py` 等调用方通过该抽象访问用户资源。

### 3. 作用域本地文件接口 (Scoped Local File Interface) [可选]
**模块**：`backend/core/storage/scoped_local_fs.py` ⏳ 按需实现

仅在原生环境确实需要访问主机文件系统时启用。它不提供通用的裸文件访问能力，而是把所有读、写、改、保存都限制在用户专属根目录或任务专属工作区内。

```python
class ScopedLocalFS:
    """本地文件系统的作用域封装"""

    def __init__(self, user_id: str, thread_id: str, root_dir: Path):
        self.user_id = user_id
        self.thread_id = thread_id
        self.root_dir = root_dir / "users" / user_id / "threads" / thread_id

    async def read_file(self, relative_path: str) -> bytes:
        """只允许读取用户目录下相对路径的文件"""
        safe_path = self._validate_path(relative_path)
        return await aio_read(self.root_dir / safe_path)

    async def write_file(self, relative_path: str, content: bytes) -> None:
        """只允许写入用户目录下相对路径的文件"""
        safe_path = self._validate_path(relative_path)
        await aio_write(self.root_dir / safe_path, content)
```

**当前状态**：不存在，无此类需求时可跳过。

### 4. 作用域 Skills 接口 (Scoped Skills Interface)

> **详细方案请参考**：[Skills动态加载与多用户隔离实施方案](./skill_dynamic_tool_loading_plan.md)

**模块**：`backend/core/skills/scoped_skills_provider.py` ✅ 已实现

在非沙箱模式下，Skills 无法通过容器挂载访问，必须通过统一接口从本地文件系统读取并注入到 Agent 提示词中。核心类 `ScopedSkillsProvider` 提供：
- `get_available_skills_for_user()` - 获取用户可用的 Skills 列表
- `build_skills_prompt_section()` - 构建与当前运行时一致的 prompt section
- `read_skill_content()` - 安全读取 Skill 文件内容

**当前状态**：Skill 解析由 `backend/core/skills/loader.py` 负责，作用域过滤、提示词片段和安全读取由 `ScopedSkillsProvider` 统一提供。

### 5. 智能体准入规范 (Agent Onboarding)

所有后续智能体 profile 与执行器必须遵循以下集成规范：
- **配置透传**：在 `ainvoke/aquery_stream` 时，必须确保 `user_id` 已注入 `RunnableConfig`。
- **Skills 动态配置**：通过 `selected_skills: set[str]` 参数动态指定 Agent 使用的 Skills 组合，不再依赖沙箱挂载。
- **工具加固**：如果启用原生工具，必须使用通过 `ScopedStorage` 加固的版本。
- **本地文件约束**：如果原生模式需要文件读写，必须使用 `ScopedLocalFS` 这类受限接口，禁止直接暴露任意路径的读、写、保存工具。
- **工具准入**：由 `ToolRegistry + ToolPolicy + ToolAssemblyPipeline` 决定工具集合，profile 执行器不得自行拼接原生或沙箱工具。
- **原生工具约束**：原生存储工具必须通过 `ScopedStorage` 获取用户与会话前缀；需要本地文件能力时应先提供受限文件系统抽象，不得直接暴露任意路径工具。
- **沙箱能力扩展**：后续如恢复沙箱工具，应注册为独立工具提供者并由策略显式授权，禁止在具体 Agent 类中根据开关分支装配。

## 六、多用户 Skills 组合隔离方案

### 核心要点

- **用户级 Skills 可见性**：不同用户可配置不同的 Skills 组合
- **动态加载**：用户选择使用哪些 Skills，Agent 动态加载

| `read_local_skill_file` | Skills 文件 | `ScopedSkillsProvider` 过滤 |

### 阶段 P1：工具加固与链路改造

#### P1-1 改造 Agent Tools
- 重构 `backend/core/tools/minio_tools.py`
- **改造要点**：
  - 强制校验 `user_id` 必须从 `thread_id` 中解析出来，拒绝外部传入的裸 `user_id`
  - 移除 `user_id is None` 时的 fallback 逻辑（这是潜在越权点）
  - 统一使用 `ScopedStorage` 封装
  - **`list_minio_objects` 必须注入 `config: RunnableConfig` 参数**，从 thread_id 解析 user_id 后强制限定 prefix 为 `users/{user_id}/` 前缀，拒绝传入其他用户前缀
  - **`upload_local_folder_to_minio` 同理**，minio_prefix 必须在函数内部根据 user_id 构造，不接受外部传入

#### P1-2 结果持久化与上传隔离
- **`result_persister.py`**：
  - 当前 `object_name = f"results/{document_id}/{task_id}.md"` 无用户前缀
  - 需改为 `f"users/{user_id}/results/{document_id}/{task_id}.md"`
  - 需将 `get_user_minio_bucket_name()` 替换 `settings.minio_bucket_name`
- **`uploads.py`**：
  - 当前 `upload_to_minio()` 直接使用 `settings.minio_bucket_name`
  - 知识库上传链路有独立的 KB 权限体系，暂不在本方案范围内
    - `uploads.py` 继续使用默认公共桶属于设计例外（KB 专用公开上传链路），无需切换到用户桶

### 阶段 P2：数据迁移与回收

- **迁移脚本**：`migrate_minio_user_prefix.py` 将历史 document/artifact 按照 `u_{uid}` 重新归类
- **双读策略**：在 `ScopedStorage.read_file` 中保留一个版本的 Fallback 逻辑（仅用于兼容旧数据）

```python
async def read_file(self, filename: str) -> bytes:
    object_name = f"{self.prefix}{filename}"
    try:
        return await self._read_object(object_name)
    except FileNotFoundError:
        legacy_name = f"artifacts/{self.thread_id}/{filename}"
        try:
            return await self._read_object(legacy_name)
        except FileNotFoundError:
            raise FileNotFoundError(f"文件不存在: {filename}")
```
