# 学习偏好测评功能设计方案

> **状态**：✅ 已实现（最后同步：2026-07-09）
> **联动**：`apply_to_ai` 开关已接入**自定义学习**计划生成（`style_snapshot`）；主 Agent 问答 Prompt **尚未**自动注入学习偏好。

## 1. 背景与目标

在现有“知识问答”和“探索式学习”之外，增加“学习偏好测评”入口，帮助用户了解自己当前更偏好的信息加工、感知、输入和理解方式，并获得可执行的学习策略建议。

本功能借鉴 Felder-Silverman 四维框架的结构，但不复制受版权保护的 ILS 原题。项目使用自编中文题库，并将结果定位为“当前学习偏好”，不作为能力、人格或教学效果诊断。

## 2. 功能范围

### 2.1 MVP 范围

- 4 个测评维度，每个维度 11 道二选一题，共 44 题。
- 桌面端采用左侧维度导航、右侧题目列表、底部固定总进度的布局。
- 移动端采用顶部维度与进度、单列题目卡片、底部操作栏。
- 自动保存答案，支持退出后继续。
- 登录用户将答题记录与结果保存到服务端；访客保存在浏览器本地。
- 结果页展示四个连续维度、偏好强度、优势描述与学习建议。
- 支持重新测试并保留登录用户的历史测评记录。
- 提供“应用于智能助手”开关，为后续回答个性化预留配置。
- 当前题库版本为 `QUESTIONNAIRE_VERSION = "2026.1"`，由 `backend/services/learning_style_assessment.py` 统一提供维度、题目、计分和解释文案。

### 2.2 暂不包含

- 不根据结果改变知识检索范围、答案正确性标准或考试评分。
- 不向教师或管理员提供个人结果排行榜。
- **主 Agent 问答**不在 Prompt 中自动注入学习偏好（`apply_to_ai` 当前仅影响自定义学习计划的 `style_snapshot` 与节点任务/详解建议）。

## 3. 四个测评维度

| 维度 | 方向 A | 方向 B | 含义 |
| --- | --- | --- | --- |
| 信息加工 | 活跃型 | 沉思型 | 倾向通过行动讨论，或独立思考来加工信息 |
| 信息感知 | 感知型 | 直觉型 | 倾向事实细节与实践，或概念规律与可能性 |
| 信息输入 | 视觉型 | 言语型 | 倾向图像结构，或文字语言形式的信息 |
| 理解方式 | 序列型 | 综合型 | 倾向逐步推进，或先把握整体框架 |

## 4. 用户流程

1. 用户从一级导航进入“学习偏好”。
2. 无进行中测评或历史结果时展示引导页，说明时长、题量和结果边界。
3. 点击“开始测评”后创建测评记录。
4. 用户按维度答题，选择答案后立即本地更新并自动保存。
5. 当前维度 11 题完成后可进入下一维度。
6. 44 题全部完成后提交并生成结果。
7. 结果页可切换“应用于智能助手”，或发起重新测试。

当前前端入口为 `frontend/src/views/learning-style/index.vue`，路由包含 `/learning-style` 与 `/m/learning-style`，均复用同一响应式页面。题库接口可匿名访问；登录用户的答题记录写入服务端，访客答题由前端本地状态完成，不创建服务端 attempt。

## 5. 计分与解释

每个维度 11 道题，A 方向记 `+1`，B 方向记 `-1`：

```text
维度得分 = A 选项数量 - B 选项数量
```

得分范围为 `-11` 到 `+11`。正数表示偏向 A，负数表示偏向 B，绝对值表示偏好强度：

- `1-3`：相对均衡
- `5-7`：中等偏好
- `9-11`：明显偏好

由于每个维度包含 11 道题，完整作答后的得分为奇数，不会出现 0。结果使用连续刻度展示，不将用户固化为单一类型。

## 6. 页面设计

### 6.1 引导页

- 标题、四维简介、44 题与预计用时。
- 明确提示“结果代表偏好而非能力，不存在好坏”。
- 登录用户若存在未完成记录，显示“继续测评”。

### 6.2 答题页

- 左侧展示四个维度、完成数量和进度条。
- 主区域一次展示当前维度 11 道题，每题两个大按钮。
- 顶部显示当前维度名称和两端方向。
- 底部显示总进度、维度圆点及“下一维度/查看结果”。
- 切换维度或离开页面前保存当前答案。

### 6.3 结果页

- 四维结果卡片展示刻度、方向、强度与双方得分。
- 提供综合说明和每个维度的学习策略。
- 提供“应用于智能助手”开关与“重新测评”按钮。
- 固定展示科学性说明，避免将偏好误解为不可改变的能力标签。

## 7. 数据模型

### 7.1 learning_style_attempts

- `attempt_id`：测评记录 ID。
- `user_id`：用户 ID。
- `questionnaire_version`：题库版本。
- `status`：`in_progress` 或 `completed`。
- `answers`：题号到选项的 JSON 映射。
- `scores`：四维原始分 JSON。
- `result`：提交时生成的完整解释 JSON。
- `current_dimension`：当前维度序号。
- `completed_at`、`created_at`、`updated_at`。

### 7.2 learning_style_profiles

- `user_id`：用户 ID，主键。
- `latest_attempt_id`：当前采用的测评记录。
- `scores`、`result`：当前结果快照。
- `apply_to_ai`：是否允许智能助手使用偏好。
- `created_at`、`updated_at`。

提交测评时，后端会用 `score_answers()` 重新计算 `scores/result`，创建或更新当前用户的 `learning_style_profiles`，并将 `latest_attempt_id` 指向本次完成记录。重新测试不会删除旧 attempt。

## 8. API 设计

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/learning-style/questionnaire` | 获取题库和维度定义 |
| GET | `/api/v1/learning-style/attempts/current` | 获取当前未完成记录 |
| POST | `/api/v1/learning-style/attempts` | 创建新测评 |
| PUT | `/api/v1/learning-style/attempts/{id}/answers` | 保存答案与当前维度 |
| POST | `/api/v1/learning-style/attempts/{id}/submit` | 校验 44 题并生成结果 |
| GET | `/api/v1/learning-style/profile` | 获取当前结果 |
| PATCH | `/api/v1/learning-style/profile/preferences` | 更新 AI 应用开关 |

题库接口允许访客访问，其余接口要求登录。访客测评由前端使用相同计分规则在本地完成。

### 8.1 当前接口行为

| 接口 | 当前行为 |
| --- | --- |
| `GET /questionnaire` | 返回 `version`、`question_count`、`dimensions`、`questions`，无鉴权 |
| `GET /attempts/current` | 返回当前用户最近的 `in_progress` 记录；无记录时 `attempt=null` |
| `POST /attempts` | 创建新 `in_progress` 记录，`questionnaire_version=2026.1`，`current_dimension=0` |
| `PUT /attempts/{id}/answers` | 校验题号和选项，保存局部答案与当前维度；只允许本人记录 |
| `POST /attempts/{id}/submit` | 要求 44 题完整，状态改为 `completed`，写入 profile 快照 |
| `GET /profile` | 返回当前用户 profile；未完成测评时 `profile=null` |
| `PATCH /profile/preferences` | 只更新 `apply_to_ai`；未生成 profile 时返回 404 |

## 9. AI 个性化预留

当前仅在用户主动开启后，将结果转换为自定义学习的轻量表达偏好：

- 活跃型：增加练习、操作任务和即时反馈。
- 沉思型：增加思考提示、停顿点和阶段总结。
- 感知型：增加事实、案例和实际应用。
- 直觉型：增加原理、联系和开放性问题。
- 视觉型：增加表格、流程图和 Mermaid 图。
- 言语型：加强文字解释、定义与类比。
- 序列型：使用明确的递进步骤。
- 综合型：先给全局框架，再展开细节。

这些偏好当前由 `custom_learning.py` 中的 `_style_dimensions()`、`_style_task_hints()`、`_style_explanation_hint()`、`_style_strategy()` 读取，用于计划生成、节点任务和详解提示。主 Agent 问答还没有自动加载该 profile。偏好只能调整表达形式，不能减少必要信息，也不能限制用户接触其他有效学习方式。

## 10. 验收标准

- 桌面和移动路由均可进入测评。
- 44 题与四个维度数量正确，未答完不能提交。
- 刷新页面后访客和登录用户都能恢复进行中记录。
- 服务端拒绝非法题号、非法选项和非本人记录。
- 四维计分方向、强度和结果文案有自动化测试。
- 重新测试不会删除旧记录。
- 前端 TypeScript 检查和生产构建通过。

## 11. 风险与边界

- 原版 ILS 页面声明版权所有，因此本项目只采用四维结构，自行编写中文题目。
- 学习偏好存在情境性和可变化性，结果页必须避免“天生类型”等绝对表述。
- 现有研究不足以证明按学习风格匹配教学媒介必然提高成绩，因此本功能用于自我反思和策略拓展，不做效果保证。
