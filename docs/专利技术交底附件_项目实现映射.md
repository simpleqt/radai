## 二、已有实现与专利步骤对应关系

| 专利技术环节 | 项目实际实现 | 结合方式 |
|---|---|---|
| 文档解析与入库 | RAGAnything、LightRAG、Markdown直入库、MinerU/Docling解析 | 已有文本块、实体、关系和多模态入库基础 |
| 实体向量召回 | `backend/rag/retriever/entity_recall.py` Path-A | 使用查询及高层关键词向量搜索实体索引，并作RRF融合 |
| 关键词召回 | `entity_recall.py` Path-B、Redis BM25 | 原查询加核心关键词扩展，执行RRF融合 |
| 文本块向量召回 | `backend/rag/retriever/chunk_searcher.py` Path-C | 直接搜索Milvus文本块集合，保留文件路径及全文档标识 |
| 知识图谱扩展召回 | `backend/rag/retriever/graph_expander.py` Path-D | NebulaGraph受限多跳扩展、边权阈值和双向邻域传导 |
| DirectRetriever四路召回服务 | `backend/rag/retriever/direct_retriever.py` | Path-A/B与Path-C并行，随后执行依赖种子的Path-D |

| 候选融合 | `backend/rag/retriever/fusion.py` | 边感知实体截断、实体覆盖率、文本块综合分和双源奖励 |

| 多样性排序 | `backend/rag/content_filter/mmr_reranker.py` | 稠密向量MMR，保护高层关键词相关文本块 |
| 统一检索入口 | `backend/rag/retrieval_pipeline.py` | `retrieve_context`统一服务HTTP和Agent工具；Direct失败可回退LightRAG mix |

| Agent Service API基础 | `backend/api/routers/agent_runtime_v2.py`、`backend/application/agent_service.py` | 已有智能体运行入口与应用服务，可承载结构化检索状态和补检索调度信息 |
| 探索式学习智能体基础 | `backend/domain/agents/workflows.py`、`retrieval_policy.py` | 已有工作流及检索策略基础，需新增证据槽位状态、补充查询及终止条件控制 |
| 多库融合 | `backend/application/tools/providers/multi_kb_search_tool.py` | 多知识库并发检索并以RRF融合 |
| 来源基础字段 | `file_path`、`full_doc_id`、`source_id`、chunk id | 可扩展页码、章节、表格号、公式号和版本字段 |

## 三、需要新增或强化的实施功能

1. 将现有关键词及QueryType解析扩展为\(\{E,P,U,C,T,I\}\)，增加参数值、单位、设备型号和工况抽取；
2. 建立单位与量纲本体、参数合理范围表、设备兼容矩阵、带方向物理信号链和工况匹配规则；
3. 在DirectRetriever候选池和现有Stage-2之间增加物理一致性校验层；
4. 将QueryType静态策略矩阵扩展为“查询类型基础权重×实时通道有效性”的动态权重；
5. 新增查询类型证据槽位模板、覆盖率计算、关键槽位规则和补检索控制器；
6. 补充页码、章节、段落、表格号、公式号和版本等入库元数据；
7. 将冲突候选按设备、工况和版本分组输出；
8. 对故障或异常查询实现异常值保留与异常证据标记，避免正常范围规则误删故障证据。
