> **文档定位**：本文件为「探索式学习」新模块的**完整设计与实施方案**，覆盖前端导航改造、交互设计、前后端接口契约、LLM/RAG 接地、分阶段实施计划与验收标准。
>
> **目标前端**：`frontend/`（RadAI = 核电子学智能助手，开发端口 `5173`）。`frontend_csh_ai/`（成理 CSH-AI）结构同构，可在二期按相同方案复用。
>
> **创建日期**：2026-05-29
>
> **状态**：✅ **一期已实现**（2026-05）— 路由 `/explore`、`/m/explore`，API `/api/v2/explore/*`  
> **现行说明**：[docs/explore_learning.md](../docs/explore_learning.md) · [docs_backend/explore_module.md](../docs/docs_backend/explore_module.md) · [docs_frontend/explore_module.md](../docs/docs_frontend/explore_module.md)

## 一、背景与目标

### 1.1 背景

当前 RadAI 前端（`frontend/src/views/ne-full/index.vue`）的核心体验是**单一的「知识问答」对话页**：

- 左侧 `HistorySidebar` 仅承载「新会话 + 历史会话列表 + 个人文件库 + 用户信息」。
- 主区域是消息流 + 输入框 + Artifact 侧栏。
- **不存在产品级的「一级导航栏（Nav Rail）」**，无法在「问答 / 探索 / 自定义学习 / 智能体广场 / 案例库」等多个学习模式间切换。

用户提供的三张截图描绘了一个新的**「探索式学习」模式**，包含三种典型形态：

1. **发现态（Topic Galaxy）**：一片漂浮的主题气泡 + 居中的「探究式学习」输入框，引导用户输入主题或点选已有知识点开启探索。
2. **思维导图态（Mind-Map）**：输入主题后生成「根节点 → 子知识点」的横向脑图，可逐级展开；点击节点弹出右侧详情抽屉。
3. **知识面板态（Knowledge Panel）**：右侧抽屉含三个 Tab —— **知识点详解**（Markdown 长文）、**关联资源**、**习题练习**（题库：选择/判断/简答/计算，支持难度筛选、随机出题、自定义出题、查看答案）。

### 1.2 目标

1. 在前端引入**一级导航栏（Nav Rail）**，作为多学习模式入口；本期落地「知识问答（沿用现有对话）」与「探索式学习（新建）」两项，其余项（自定义学习 / 智能体广场 / 案例库）以占位形式预留，后续迭代。
2. 完整实现「探索式学习」三态闭环：**发现 → 脑图探索 → 知识详解/关联资源/习题练习**。
3. 内容**全程接地（grounded）于核电子学知识库**：脑图节点、知识详解、关联资源、习题均通过 `retrieve_context` 检索 KB 上下文后再交由 LLM 生成，保证专业性与可溯源。
4. 复用现有技术栈与封装（Vue3 + Tailwind + `request()` + SSE 流式 + `create_chat_model`），**不引入重型可视化依赖**，保持包体与代码风格一致。

### 1.3 相对截图的改进点（我们的优化方案）

| 截图原状 | 本方案优化 |
|---|---|
| 发现态气泡为静态随机分布 | 气泡基于**当前知识库主题/高频实体**动态生成，带轻量浮动动画与 hover 释义，点击即作为脑图根节点 |
| 脑图节点点击仅看详解 | 节点支持**逐级 LLM 扩展（按需展开子知识点）**，避免一次性生成过深的树；导图支持折叠/聚焦/重置 |
| 知识详解为一次性静态文本 | 详解采用 **SSE 流式输出 + Markdown/KaTeX 渲染 + 来源引用脚注**，与现有问答体验统一 |
| 关联资源未定义来源 | 关联资源直接来自 **KB 检索命中的文档/Chunk**，可跳转「个人文件库 / 知识库文档」，真实可溯源 |
| 习题为静态题库 | 习题由 **LLM 基于该知识点的 KB 上下文实时生成**，支持题型/难度筛选、随机/自定义出题，简答/计算题支持 **LLM 评分与解析** |
| 无会话留存 | 探索过程（脑图 + 已生成内容）支持 **localStorage 草稿留存**（访客）/ **后端持久化**（登录用户，二期可选） |

## 三、总体设计

### 3.1 信息架构与导航改造

引入**一级导航栏（Nav Rail）**，作为应用的最左侧固定竖条；其右侧再渲染各模块自身的「二级侧栏 + 主区」。

```
┌──────┬──────────────────────────────────────────────────────┐
│ Nav  │  [模块自有布局]                                          │
│ Rail │                                                         │
│      │  知识问答  → HistorySidebar + 对话主区 + Artifact 侧栏      │
│ ◉问答 │  探索式学习 → (发现态 | 脑图态) + 右侧知识面板抽屉            │
│ ○探索 │                                                         │
│ ○自定义│  自定义学习/智能体广场/案例库 → 占位页（Coming Soon）         │
│ ○广场 │                                                         │
│ ○案例 │                                                         │
│      │                                                         │
│ 用户  │                                                         │
└──────┴──────────────────────────────────────────────────────┘
```

**实现策略（低侵入）**：

- 新建布局组件 `src/app/layouts/AppShell.vue`，内含 `NavRail.vue` + `<router-view>`。
- `知识问答` 与 `探索式学习` 作为 `AppShell` 的子路由渲染；Nav Rail 通过 `router.push` 切换，高亮当前激活项。
- **保持现有 `/app` 行为不变**：将 `ne-full/index.vue` 作为 `AppShell` 下 `/app` 的子视图渲染（移除其内部对全屏布局的假设，或用 `inShell` prop 兼容）。为降低风险，一期可采用**「Nav Rail 以浮层/侧贴形式叠加在现有页面左缘」**的渐进方案（见 §6.1 方案A/B 取舍）。

> 导航项配置集中在 `src/app/navigation.ts`，便于后续增删模块与权限控制。

### 3.2 模块划分（探索式学习内部）

```
探索式学习 (Explore Module)
├── 发现态 TopicGalaxy        —— 主题气泡 + 中央输入，开启探索
├── 脑图态 MindMapCanvas      —— 根节点/子节点树，逐级 LLM 扩展
│   └── MindMapNode           —— 单节点（标题/展开/选中）
└── 知识面板 KnowledgePanel    —— 右侧抽屉，三 Tab：
    ├── 知识点详解 DetailTab    —— SSE 流式 Markdown + 来源引用
    ├── 关联资源 ResourcesTab  —— KB 命中文档/Chunk 列表/搜索到的网页
    └── 习题练习 QuizTab        —— 题库（题型/难度筛选、出题、答案、评分）
```

### 3.3 端到端数据流

```
用户输入主题 / 点击气泡
   │
   ▼  POST /api/v2/explore/map   {topic, kb_ids}
① 脑图生成：retrieve_context(topic) → LLM 生成 {root, children[]}（JSON）
   │
   ▼  前端渲染脑图；点击某节点
② 节点展开：POST /api/v2/explore/expand {node, path, kb_ids} → 子节点 JSON
   │
   ▼  打开右侧知识面板（默认「知识点详解」Tab）
③ 详解：POST /api/v2/explore/detail (SSE) → 流式 Markdown（含引用）
④ 资源：GET  /api/v2/explore/resources {node, kb_ids} → KB 命中文档/Chunk
⑤ 习题：POST /api/v2/explore/quiz {node, types, difficulty, count} → 题目 JSON
⑥ 评分(可选)：POST /api/v2/explore/quiz/grade {question, user_answer} → 评分+解析
```

## 四、交互与界面设计

### 4.1 发现态（TopicGalaxy）

- **中央卡片**：标题「探究式学习」+ 副标题引导语 + 大号输入框（圆角、聚焦发光），回车或点搜索按钮 → 进入脑图态。
- **气泡云**：围绕中央散布 16–24 个主题气泡（来自 `POST /api/v2/explore/topics`，基于 KB 主题/高频实体）。
  - 气泡带**轻量浮动动画**（CSS `@keyframes`，错相位 transform，禁用 `prefers-reduced-motion` 时停用）。
  - hover 显示一行释义 tooltip；点击 → 以该主题作为根节点进入脑图态。
- **KB 选择器**：复用 `agent/info` 的 `available_kbs`，允许切换探索所基于的知识库（默认核电子学库）。
- 空/加载/错误态均有骨架屏与重试。

### 4.2 脑图态（MindMapCanvas）

- **布局**：横向层级树（根在左，子节点向右展开），自绘 SVG 贝塞尔连线 + HTML 节点卡片（便于富文本/图标/交互）。
- **节点交互**：
  - 点击节点标题 → 选中并打开右侧知识面板。
  - 节点右侧「⊕ 展开」按钮 → 调 `expand` 生成下一级子节点（带 loading）。
  - 节点折叠/展开、画布拖拽平移、滚轮缩放、`重置/聚焦根` 工具条。
- **顶部**：返回发现态、当前主题面包屑、KB 切换、重新生成。
- **性能**：树节点超过阈值（如 80）时停止自动展开并提示。

### 4.3 知识面板（KnowledgePanel，右侧抽屉）

抽屉头部：节点标题 + 关闭按钮；下方三 Tab（radix-vue `Tabs`）。

1. **知识点详解 DetailTab**
   - 进入即发起 `detail` SSE，**流式**渲染 Markdown（复用 `MarkdownRenderer.vue`，支持 KaTeX 公式/表格/图示占位）。
   - 底部「来源引用」折叠区：列出 `retrieve_context` 命中的文档名/片段，点击定位。
   - 操作：复制、加入笔记（二期）、再次生成。

2. **关联资源 ResourcesTab**
   - 调 `resources` 返回 KB 命中条目：`{doc_id, doc_name, snippet, score, kb_id}`。
   - 卡片列表，支持跳转知识库文档详情 / 个人文件库；空态友好提示。

3. **习题练习 QuizTab**（对齐截图「题库管理」）
   - 顶部：题型筛选（全部/选择/判断/简答/计算）+ 难度下拉（全部/简单/中等/困难）+「随机出题」「自定义出题」按钮。
   - 题目卡片：题号、题型标签、难度标签、题干、选项（单选）/输入框（简答/计算）、「查看答案/参考答案」折叠。
   - 简答/计算题支持「提交评分」→ `quiz/grade` 返回得分 + 逐点解析。
   - 分页（前端分页或 `count` 增量加载）。

### 4.4 响应式与可访问性

- **桌面**（`/explore`）：Nav Rail + 脑图主区 + 右侧抽屉并列。
- **移动**（`/m/explore`）：发现态为竖向列表；脑图态为可横滑/纵向折叠的层级列表；知识面板为**底部 Sheet**。
- 键盘可达（Tab 焦点、Enter 触发）、`aria-*` 标注、`prefers-reduced-motion` 降级动画。

## 五、接口契约（API Contract）

所有探索端点统一挂载于 `/api/v2/explore`（新建 `backend/custom/api/v2/explore.py`，前缀 `/explore`，由 v2 `api_router` 聚合）。鉴权：登录用户走 `get_current_user`；未登录允许调用但不持久化（与访客问答一致）。

### 5.1 `POST /api/v2/explore/topics` — 发现态主题气泡

请求：
```json
{ "kb_ids": ["<kb_id>"], "count": 20, "seed": "可选：聚焦子领域" }
```
响应：
```json
{
  "topics": [
    { "id": "t_xxx", "title": "核电子学基础", "hint": "信号链与测量系统概览" },
    { "id": "t_yyy", "title": "脉冲成形电路", "hint": "..." }
  ],
  "kb_id": "<kb_id>",
  "source": "llm|fallback"
}
```

### 5.2 `POST /api/v2/explore/map` — 生成脑图（根 + 一级子节点）

请求：
```json
{ "topic": "核电子学基础", "kb_ids": ["<kb_id>"], "max_children": 6 }
```
响应：
```json
{
  "root": { "id": "n_root", "title": "核电子学基础", "summary": "一句话概述" },
  "children": [
    { "id": "n_1", "title": "脉冲信号传输技术", "summary": "...", "expandable": true },
    { "id": "n_2", "title": "核电子学系统构成", "summary": "...", "expandable": true }
  ],
  "kb_id": "<kb_id>",
  "source": "llm|fallback"
}
```

### 5.3 `POST /api/v2/explore/expand` — 展开某节点的下一级

请求：
```json
{ "node_title": "脉冲信号传输技术", "path": ["核电子学基础"], "kb_ids": ["<kb_id>"], "max_children": 5 }
```
响应：
```json
{ "children": [ { "id": "n_11", "title": "...", "summary": "...", "expandable": true } ], "source": "llm" }
```

### 5.4 `POST /api/v2/explore/detail` — 知识点详解（SSE 流式）

请求：
```json
{ "node_title": "核电子学基础", "path": ["核电子学基础"], "kb_ids": ["<kb_id>"], "model": "可选" }
```
响应：`text/event-stream`，逐行 `data: {json}`，复用现有事件协议：
```
data: {"type":"status","content":"正在检索知识库…"}
data: {"type":"chunk","content":"## 核电子学基础详解\n\n核电子学..."}
data: {"type":"chunk","content":"……"}
data: {"type":"event","event":{"kind":"sources","metadata":{"sources":[{"doc_id":"...","doc_name":"...","snippet":"..."}]}}}
data: [DONE]
```
> 前端复用 `api/agent-v2.ts` 的 SSE 解析（建议抽取 `utils/sseClient.ts` 通用读取器）。

### 5.5 `GET /api/v2/explore/resources` — 关联资源

请求（query 或 POST body）：`node_title`, `kb_ids`, `top_k=8`。
响应：
```json
{
  "resources": [
    { "doc_id": "d_1", "doc_name": "核电子学讲义.pdf", "snippet": "前置放大器…", "score": 0.83, "kb_id": "<kb_id>", "category_path": "/讲义" }
  ]
}
```
> 直接由 `retrieve_context(node_title, kb_id, chunk_top_k=top_k)` 的命中 chunk 聚合去重得到。

### 5.6 `POST /api/v2/explore/quiz` — 生成习题

请求：
```json
{
  "node_title": "核电子学基础",
  "kb_ids": ["<kb_id>"],
  "types": ["choice", "judge", "short", "calc"],
  "difficulty": "all|easy|medium|hard",
  "count": 6
}
```
响应：
```json
{
  "questions": [
    {
      "id": "q_1", "type": "choice", "difficulty": "easy",
      "stem": "在核电子学系统中，前置放大器的主要作用是？",
      "options": [
        {"key":"A","text":"对信号进行时间分析"},
        {"key":"B","text":"将探测器输出的微弱信号进行初步放大和阻抗匹配"},
        {"key":"C","text":"测量辐射剂量率"},
        {"key":"D","text":"产生标准脉冲信号"}
      ],
      "answer": "B",
      "explanation": "前置放大器…",
      "source_refs": ["d_1"]
    },
    {
      "id": "q_2", "type": "judge", "difficulty": "easy",
      "stem": "核电子学系统中的主放大器仅负责信号放大，不影响信号形状。",
      "answer": "错误", "explanation": "主放大器同时承担成形…"
    },
    {
      "id": "q_3", "type": "short", "difficulty": "medium",
      "stem": "简述核电子学系统中脉冲成形电路的作用及其主要类型。",
      "reference_answer": "脉冲成形的作用是…；主要类型包括 CR-RC、…",
      "scoring_points": ["提高信噪比", "防止堆积", "CR-RC/梯形/高斯成形"]
    }
  ],
  "source": "llm|fallback"
}
```
题型枚举：`choice`(单选) | `multi`(多选，可选) | `judge`(判断) | `short`(简答) | `calc`(计算)。

### 5.7 `POST /api/v2/explore/quiz/grade` — 主观题评分（可选，二期）

请求：`{ "question": {...}, "user_answer": "..." }`
响应：`{ "score": 0..100, "verdict": "正确|部分正确|错误", "feedback": "...", "missing_points": ["..."] }`

### 5.8 错误与降级约定

- 所有生成端点：LLM 超时（`asyncio.wait_for`）或 JSON 解析失败 → 返回 `source:"fallback"` 的模板内容（脑图给通用骨架、习题给占位提示），HTTP 200，避免前端崩溃（参考 `follow_up_suggestions.py` 兜底范式）。
- KB 未命中：详解/资源退化为「纯 LLM 通识 + 无来源」并在响应标注 `grounded:false`。

## 八、关键技术点与降级策略

1. **JSON 稳健解析**：复用 `follow_up_suggestions.py` 的正则提取 + `json.loads` 容错（兼容 ```` ```json ```` 包裹、多余前后文）；解析失败即 fallback。
2. **超时控制**：生成端点用 `asyncio.wait_for`（脑图/习题 ~15s，topics ~8s）；详解流式无硬超时但有心跳与中断（`AbortSignal`）。
3. **缓存**：对「同一 (node_title, kb_id)」的详解/资源/习题做短期内存缓存（LRU/TTL，参照现有 KB 缓存习惯）以降本提速。
4. **接地优先**：检索命中为空时标注 `grounded:false`，前端展示「通识内容（未引用知识库）」提示，避免误导。
5. **并发与防抖**：节点连续点击展开做去重 in-flight 控制；详解切换节点时 `abort` 上一条 SSE。
6. **安全**：Markdown 经 `dompurify` 渲染（沿用 `MarkdownRenderer.vue`）；后端对 `kb_ids` 做权限校验（登录用户仅可访问其可见 KB）。
