# 知识库管理接口说明文档

> **文档状态**：📦 历史草案（2026-03 前后）。**现行 API 以 Swagger 为准**：`http://<api_host>:<api_port>/docs`  
> **速查**：[docs/api_quick_reference.md](../docs/api_quick_reference.md) · **管理后台入库**：[docs/docs_frontend/admin_module.md](../docs/docs_frontend/admin_module.md)  
> **图库**：生产为 **NebulaGraph**（每 KB 独立 Space），非 Neo4j。

## 概述

本文档描述知识库/RAG 相关 HTTP 接口及历史规划项。多知识库场景下，向量/图数据按 `kb_id` 隔离（Milvus collection、`NebulaGraph` Space）。

**数据存储组件（现行）**：

| 组件 | 用途 |
| :--- | :--- |
| **MySQL** | `file_info`、`knowledge_bases`、`pending_files` 等 |
| **Redis** | LightRAG KV、BM25、Token |
| **Milvus** | 实体/chunk/关系向量、`keyword_index` |
| **NebulaGraph** | 实体与关系图（Path-D 扩展） |

---

## 已暴露 HTTP 接口（`/api/v1/rag`）

实现：`backend/api/routers/rag.py`

### 1. 查询可用模型列表

```http
GET /api/v1/rag/models
Authorization: Bearer <token>  或  X-API-Key: <key>
```

### 2. RAG 健康检查

```http
GET /api/v1/rag/health
```

### 3. 根据 doc_id 删除文档

```http
POST /api/v1/rag/delete_doc
Content-Type: application/json

{
  "doc_id": "xxx",
  "delete_llm_cache": false
}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| doc_id | string | 是 | 文档 ID |
| delete_llm_cache | boolean | 否 | 是否删除 LLM 缓存 |

### 4. 检索（生产主路径）

```http
POST /api/v1/rag/retrieve
POST /api/v1/rag/retrieve_internal
```

请求体含 `query`、`kb_ids` 等；编排为 **DirectRetriever + Profile**（垂直库 MMR_ONLY）。详见 [docs/知识库算法和架构.md](../docs/知识库算法和架构.md)。

### 5. 其他（运维/调试）

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| POST | `/api/v1/rag/query_stream` | RAG 流式问答 |
| POST | `/api/v1/rag/insert` | 插入内容 |
| POST | `/api/v1/rag/reset` | 重置（慎用） |
