# 通用表格分析能力方案

> 文档状态：方案设计  
> 最后更新：2026-06-04  
> 适用范围：NE 全功能智能体、CSH 全功能智能体、轻量问答模式、对话文件上传  
> 核心目标：让表格分析成为通用能力，而不是某个专业方向 skill 才具备的能力。

---

## 一、背景

当前表格分析能力主要依赖 `excel-experiment-analysis` skill。它的定位偏“实验数据分析”，只有用户在 full 模式下显式选择相关 skill 后，系统才会通过 `ToolAssemblyPipeline` 注入 `inspect_excel_data`、`query_excel_data`、`summarize_excel_data`、`visualize_excel_data` 等工具。

现有路由逻辑中，NE 与 CSH 都通过 `selected_skills` 是否为空来判断模式：

1. `selected_skills` 为空：进入轻量问答模式。
2. `selected_skills` 非空：进入 full 模式。
3. deep research 独立优先。

这导致两个体验问题：

1. 轻量模式下，即使用户上传了 Excel/CSV 表格，也只能作为普通文档文本参与上下文，不能进行结构化查询、统计、可视化。
2. full 模式下，表格分析必须依赖用户选择某个 skill；如果用户只上传了表格但没有选 skill，或者选的是领域问答 skill，则表格分析工具不会自然可用。

本方案将表格能力拆成“通用表格分析能力”，不再把它理解为水文地质、核电子学、实验数据等专业技能本身。

---

## 二、目标与非目标

### 2.1 目标

1. 轻量模式：用户上传 Excel/CSV/XLS/XLSX 表格文件后，系统自动识别并动态启用表格分析能力。
2. full 模式：NE 与 CSH 两个 full 智能体默认拥有通用表格分析 skill，和当前默认问答领域 skills 一样，无需用户手动勾选。
3. 通用化：新增或改造为 `general-table-analysis` skill，定位为通用表格分析，不绑定“实验数据”或某个专业方向。
4. 复用现有工具：优先复用 `backend/custom/tools/excel_data_analysis_tool.py` 与 DuckDB/Pandas 图表能力，避免重复造一套表格引擎。
5. 保持轻量模式低延迟：没有表格文件时，不引入表格工具和额外 prompt；有表格文件时，只注入表格所需的最小能力。
6. 多轮可用：用户上传表格后，后续同一会话继续问“按地区汇总”“画趋势图”等，仍能定位到该表格。

### 2.2 非目标

1. 本期不做 Excel 在线编辑器。
2. 本期不做数据库级持久化数据仓库导入。
3. 本期不把“通用表格分析”伪装成核电子学、水文地质等专业技能。
4. 本期不要求轻量模式进入完整 LangGraph tool loop；轻量模式可以采用服务端动态前处理 + 结果注入。

---

## 三、目标行为

### 3.1 轻量模式行为

用户没有选择任何 skill，仍走轻量问答；但只要当前会话存在表格文件：

1. 上传阶段识别 `.csv`、`.xls`、`.xlsx`。
2. 后端记录该文件可作为表格分析源。
3. 用户问题命中表格分析意图时，轻量模式在回答前调用表格分析工具。
4. 工具结果以结构化上下文注入轻量模型。
5. 前端过程事件展示为“表格结构读取”“表格统计完成”“图表已生成”等。

典型问题：

1. “帮我总结这个表格”
2. “按月份统计销售额”
3. “找出缺失值最多的列”
4. “画一个收入趋势图”
5. “筛选出降解率大于 90% 的记录”

### 3.2 full 模式行为

NE 和 CSH full 智能体默认可用 `general-table-analysis`：

1. `NEFullFeatureAgent.DEFAULT_SELECTED_SKILLS` 增加 `general-table-analysis`。
2. `CSHFullFeatureAgent.DEFAULT_SELECTED_SKILLS` 增加 `general-table-analysis`。
3. 用户选择其他 skill 时，默认 skill 与用户选择合并，和当前领域问答 skill 的逻辑一致。
4. full 模式通过现有 skill prompt 与 declared tools 机制注入表格分析工具。
5. 表格问题可以由模型自主调用 `inspect_excel_data`、`query_excel_data`、`summarize_excel_data`、`visualize_excel_data`。

## 四、能力设计

### 4.1 新增通用 Skill

建议新增：

```text
backend/skills/public/general-table-analysis/SKILL.md
```

front matter：

```yaml
---
name: general-table-analysis
description: 通用表格分析能力。用于分析用户上传或系统已有的 Excel/CSV 表格，包括表结构探查、SQL 查询、统计摘要、缺失值分析、分组聚合、排序筛选和可视化图表生成。不限定专业领域。
tools:
  - inspect_excel_data
  - query_excel_data
  - summarize_excel_data
  - visualize_excel_data
---
```

说明：

1. 不声明 `list_experiment_datasets` 为核心工具，避免通用表格分析默认引导用户去找“实验数据集”。
2. 如果仍需要支持服务器预置数据集，可以在 skill 中写成“可选能力”，但主工作流应以用户上传文件为第一入口。
3. 原 `excel-experiment-analysis` 可保留，用于实验数据集和跨数据集 JOIN 的专业分析；通用 skill 复用同一批底层工具。

### 4.2 工具装配改造

当前 `ToolAssemblyPipeline._load_declared_skill_tool()` 已支持这些表格工具名：

```text
list_experiment_datasets
inspect_excel_data
query_excel_data
summarize_excel_data
visualize_excel_data
excel_data_analysis
```

本期需要确认两点：

1. `general-table-analysis` 声明的工具名可被该方法识别并注入。
2. 如果未来把工具名改为 `inspect_table_data` 等通用名字，应保留旧工具名兼容层，避免影响 `excel-experiment-analysis`。

### 4.3 上传文件元数据改造

当前 `chat_files` 上传会把原文件上传到 MinIO，并在 `UserFile.metadata_` 中保存解析内容、类别、策略等信息。表格工具当前支持 `file_path`，但上传文件主要是 MinIO object，不一定有可直接传入 DuckDB/openpyxl 的本地路径。

建议新增“表格分析源登记”：

```json
{
  "file_category": "short_doc",
  "strategy": "context",
  "table_analysis": {
    "enabled": true,
    "source_type": "chat_file",
    "file_id": "uf_xxx",
    "file_name": "data.xlsx",
    "ext": ".xlsx",
    "storage_bucket": "...",
    "storage_object": "users/.../data.xlsx",
    "analysis_path": "/tmp/table-analysis/uf_xxx/data.xlsx",
    "sheet_names": ["Sheet1"],
    "row_counts": {"Sheet1": 1200}
  }
}
```

实现建议：

1. 上传表格文件后，保存一份受控本地缓存，或在工具调用前从 MinIO 拉取到受控缓存目录。
2. 缓存目录按 `file_id` 隔离，避免文件名冲突。
3. `analysis_path` 不直接暴露给前端，只在后端工具调用中使用。
4. 删除会话文件时，可异步清理缓存。

### 4.4 表格文件识别

新增公共判断函数：

```python
TABLE_ANALYSIS_EXTENSIONS = {".csv", ".xls", ".xlsx"}

def is_table_analysis_file(filename: str, mime_type: str | None = None) -> bool:
    ...
```

使用位置：

1. `backend/api/routers/chat_files.py` 上传完成时写入 `metadata_.table_analysis`。
2. `backend/custom/api/v2/agent.py` 和 `backend/custom/api/v2/csh_agent.py` 构建运行时问题时，按 `thread_id` 自动补全表格文件。
3. `LightweightQAAgent` 判断是否启用轻量表格分析前处理。
4. full 模式工具调用时解析 `file_id` 到后端 `analysis_path`。

## 五、轻量模式动态注入方案

轻量模式不适合直接引入完整 LangGraph tool loop，否则会破坏它“快、短路径”的定位。建议采用“服务端动态前处理”。

### 5.1 运行流程

```text
用户提问
  ↓
后端按 thread_id / file_ids 找到表格文件
  ↓
判断问题是否命中表格分析意图
  ↓
命中：调用表格工具生成结构化结果
  ↓
把结果作为 [表格分析上下文] 注入 LightweightQAAgent
  ↓
模型生成自然语言回答
```

### 5.2 轻量表格意图判断

第一版可以用规则 + 小模型判定的组合：

规则命中关键词：

```text
表格、Excel、CSV、工作表、sheet、列、字段、缺失值、统计、均值、最大值、最小值、排序、筛选、分组、汇总、趋势、图、柱状图、折线图、相关性、SQL
```

如果用户上传了表格文件，并且问题是“总结一下”“分析一下”“有什么结论”，也应视为表格分析。

### 5.3 轻量模式可执行动作

按问题类型选择工具：

| 用户意图 | 工具动作 |
|---|---|
| “这个表格有哪些列/有几个 sheet” | `inspect_excel_data(file_path=...)` |
| “总结/分析这个表格” | `inspect_excel_data` + `summarize_excel_data` |
| “按 X 分组统计 Y” | 先 `inspect_excel_data`，再生成 SQL 调 `query_excel_data` |
| “筛选/排序/Top N” | `query_excel_data` |
| “画图/可视化/趋势” | `visualize_excel_data` |

### 5.4 注入给轻量模型的上下文格式

建议在 `LightweightQAAgent` 构建 system prompt 时追加：

```text
[表格分析上下文]
数据文件：xxx.xlsx
分析动作：summarize_excel_data
工具结果：
...

回答要求：
- 先直接回答用户问题。
- 涉及数值时引用工具结果，不要臆造。
- 如果工具结果显示列名不存在，需要说明可用列名并建议用户改问法。
- 如果已生成图表，保留工具返回的 Markdown 图片链接。
```

### 5.5 轻量过程事件

前端已支持过程事件，轻量模式可复用现有 `_make_process_event`：

1. `tool_start`：表格分析开始，tool=`table_analysis`
2. `tool_end`：表格分析完成
3. `tool_result`：展示摘要或图表链接
4. `error`：列名不存在、文件无法解析、表格过大等

## 六、full 模式默认能力方案

### 6.1 默认 Skill 合并

NE：

```python
DEFAULT_SELECTED_SKILLS = ["nuclear-electronics", "general-table-analysis"]
```

CSH：

```python
DEFAULT_SELECTED_SKILLS = ["csh-hydrogeology", "general-table-analysis"]
```

当前 `_normalize_selected_skills()` 已经会合并默认 skill 与用户选择的 skill，可直接沿用。

### 6.2 Prompt 约束

full 模式 system prompt 中不需要强制每轮加载表格 skill。建议只在用户问题涉及表格或当前会话存在表格文件时要求加载：

```text
<skill_enforcement_table>
- If the user asks to analyze an uploaded Excel/CSV/table file, you MUST call read_local_skill_file("general-table-analysis") before using table analysis tools.
- For table questions, inspect the table schema before SQL/statistical analysis.
- Use uploaded file sources provided by the runtime; do not invent file paths.
</skill_enforcement_table>
```

原因：

1. full 模式默认拥有该 skill，但不应在普通领域问答中浪费 token 加载。
2. 表格问题需要先读 skill，避免模型直接盲写 SQL。

### 6.3 工具参数补足

为了避免模型不知道上传表格的 `file_path`，建议新增一个轻量工具或扩展现有工具：

方案 A：新增 `list_uploaded_table_files`

返回当前会话可分析表格：

```json
[
  {
    "file_id": "uf_xxx",
    "file_name": "data.xlsx",
    "analysis_path": "/tmp/table-analysis/uf_xxx/data.xlsx",
    "sheet_names": ["Sheet1"]
  }
]
```

方案 B：扩展现有表格工具支持 `file_id`

例如：

```python
inspect_excel_data(file_id="uf_xxx")
query_excel_data(file_id="uf_xxx", sql="...")
summarize_excel_data(file_id="uf_xxx")
visualize_excel_data(file_id="uf_xxx", chart_type="bar")
```

推荐方案 B。`file_id` 比 `file_path` 更安全，也更符合当前对话附件模型。`file_path` 可保留给后端内部和兼容旧流程。

## 七、前端与接口约定

### 7.1 前端上传提示

表格上传成功后，文件 chip 可显示“可分析表格”状态：

```text
data.xlsx · 可分析表格
```

不需要让用户手动选择 skill。

### 7.2 请求参数

现有 `file_ids` 已支持随查询发送。保持不变：

```json
{
  "question": "按月份统计销售额并画图",
  "thread_id": "...",
  "selected_skills": [],
  "file_ids": ["uf_xxx"]
}
```

轻量模式仍由 `selected_skills: []` 触发，但后端会因为 `file_ids/thread_id` 下存在表格而启用动态表格分析。

### 7.3 Agent Info

`/api/v2/agent/info` 与 `/api/v2/csh_agent/info` 可在 `features` 增加：

```text
table_analysis
dynamic_table_analysis
```

含义：

1. `table_analysis`：full 模式默认拥有通用表格 skill。
2. `dynamic_table_analysis`：轻量模式在表格上传后可动态分析。

## 八、实现步骤

### 阶段 1：通用 Skill 与 full 默认启用

1. 新增 `backend/skills/public/general-table-analysis/SKILL.md`。
2. 将 NE 默认 skill 改为 `["nuclear-electronics", "general-table-analysis"]`。
3. 将 CSH 默认 skill 改为 `["csh-hydrogeology", "general-table-analysis"]`。
4. 确认 `ToolAssemblyPipeline` 能按新 skill 声明注入表格工具。
5. 添加测试：NE/CSH `_normalize_selected_skills(None)` 均包含 `general-table-analysis`。

### 阶段 2：表格上传源登记

1. 在 `chat_files` 上传流程识别表格扩展名。
2. 为表格文件登记 `metadata_.table_analysis`。
3. 实现 `file_id -> analysis_path` 的后端解析函数。
4. 扩展表格工具支持 `file_id` 参数，内部解析到受控缓存路径。
5. 添加测试：上传表格后可通过 `file_id` 调 `inspect_excel_data`。

### 阶段 3：轻量模式动态表格分析

1. 在 `LightweightQAAgent` 增加“当前会话是否有表格文件”的检测。
2. 增加表格意图判断。
3. 命中时执行表格前处理。
4. 将工具结果注入 `[表格分析上下文]`。
5. 通过过程事件展示分析进度。
6. 添加测试：`selected_skills=[]` + 上传表格时，轻量回答会使用表格分析结果。

### 阶段 4：体验与稳态优化

1. 前端文件 chip 展示“可分析表格”。
2. 图表生成后自动进入 artifact 或消息 Markdown 图片。
3. 增加大表保护：行数、列数、图表最大行数、SQL 超时。
4. 增加错误提示：列名不存在、sheet 不存在、文件过大、图表无法生成。

## 九、风险与约束

1. 路径安全：不要把任意 `file_path` 暴露给模型，应优先使用 `file_id`。
2. SQL 安全：DuckDB 查询应限制只读，不允许访问任意本地文件、安装扩展或执行危险语句。
3. 大文件性能：上传时只做轻量 schema 预读，复杂统计放到用户提问时按需执行。
4. token 成本：轻量模式不要把完整表格文本塞入 prompt，应使用工具摘要、SQL 结果和图表链接。
5. skill 泛化：`general-table-analysis` 不应包含实验数据专属示例作为主路径，避免误导非实验场景。
6. 兼容性：保留 `excel-experiment-analysis` 给已有实验数据集流程，不做破坏性替换。

---

## 十、验收标准

1. 轻量模式上传 `xlsx/csv` 后，用户问“总结这个表格”，系统能返回表结构、关键统计和结论。
2. 轻量模式上传表格后，用户问“按某列分组统计”，系统能正确使用表格列名并返回结果表。
3. 轻量模式上传表格后，用户问“画趋势图”，系统能返回可预览图表。
4. NE full 模式不手动选择表格 skill，也能在表格问题中调用表格工具。
5. CSH full 模式不手动选择表格 skill，也能在表格问题中调用表格工具。
6. 普通轻量问答没有表格文件时，不出现额外表格分析步骤。
7. 用户上传普通 PDF/DOCX 时，不误触发表格分析能力。
8. 用户删除会话表格文件后，后续问题不再能分析该文件。

## 十二、推荐最终产品表达

对用户不展示“请选择表格 skill”。推荐表达为：

```text
已识别为表格文件，可直接提问：总结数据、分组统计、筛选排序、生成图表。
```

full 模式中也不需要把它包装成“专业技能”。它是所有智能体都具备的基础数据能力，和“能读文档、能看图片”一样，是通用能力。
